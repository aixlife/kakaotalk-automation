# Windows v0.4.0 검증 기록

기준일: 2026-11-02, 릴리스 커밋 시점 기록. **26.9.1.5339 x64의 선택 방 실제 읽기와 독립 원문 대조를 확인했습니다. x86 실제 읽기는 NOT_RUN입니다.** 아래 미완료 검사는 완료로 계산하지 않습니다. 이 보고서는 공개 가능한 버전·해시·검사 수치만 기록하며 대화·계정·방 식별자와 로컬 경로는 포함하지 않습니다.

## x64 실제 읽기

카카오톡 실행 파일 SHA-256:

```text
d7781cf275a6f4f23547e8e698005d0e8dbb78e205a34baa2eda3ea158fc64d1
```

이 실제 읽기에 결속된 런타임 소스 manifest SHA-256:

```text
6a04249ce5fab0d2b52cfb240cf979fc6157da095885894de204ad5e2b7bfa08
```

UTF-8 출력 수정까지 반영한 최종 소스로 실제 `tools/windows_probe.py run`을 실행해 선택한 방에서3건을 읽었습니다. [본문 없는 실제 proof](qa-windows-v0.4.0-proof.json)의 전체15개 런타임 소스 핀과 영수증 재검증도 통과했습니다. 동일 요청의 저장된 pending proof를 다시 회수했으며 이 회수에서 앱을 다시 읽지 않았습니다.

기존에 별도 저장한 Mac 소스45행을 참조해 실제 probe가 읽은3건의 ID와 본문을 다시 대조했습니다. 참조 소스의 `message_id`는 네임스페이스와 `log_id`를 결합한 형식이므로 네임스페이스 접두부만 제거했습니다. 본문은 수정·정규화하지 않았으며3건 모두 정확히 일치했습니다.

세 메시지의 두 소스 시각은 각각1초 차이였습니다. 시각을 보정하거나 완전히 일치한다고 판정하지 않았습니다. 이 결과는 독립 로컬 소스의 ID·본문 대조이며, 소유자가 원문·시각을 직접 확인했다는 기록이 아닙니다.

공유용 proof 상태는 `READ_VERIFIED_PENDING_OWNER_MATCH`, 소유자 확인은 미실시입니다. proof의 `independent_log_id_comparison=NOT_RUN`은 probe 자체가 독립 참조 소스를 읽지 않았다는 뜻입니다. 정식 승격 검토의 독립 소스3개 ID·본문 대조는 별도 유지보수 QA입니다. proof 자체를 소유자 확인 `PASS`로 바꾸거나 자동으로 stable 승인을 부여하지 않습니다.

프로세스와 설치 파일의 일치 확인 범위는 **매핑된 PE 헤더**입니다. `identity_scope=mapped_pe_headers_only`, `mapped_code_hash_verified=false`를 유지합니다. 디스크 실행 파일의 SHA-256과 메모리 내 전체 코드 해시 검증은 구별합니다.

## 자원과 부작용 측정

| 항목 | 관측값 | 유지한 한도 |
|---|---:|---:|
| 실제 읽기 | 2.595초 | 40초 |
| 앱 프로세스에서 읽은 바이트 | 10,487,502B | 384MiB |
| 내부 Job 최대 commit / 시간 | 64,401,408B / 3.473초 | 256MiB / 45초 |
| 외부 Job 최대 commit / 시간 | 80,162,816B / 4.085초 | 256MiB / 50초 |
| 앱 private 메모리 전·후 | 모두216,006,656B | 469,893,120B 미만 |

입력·클립보드·발신 호출은 각각0입니다. 프로세스 덤프·키·평문 DB 저장은 모두 false입니다. 카카오톡 재설치, 로그인·보안 변경, 메시지 발신은 수행하지 않았습니다. 이 호출 수치는 별도의 매 요청 화면 관찰을 뜻하지 않습니다.

큰 DB 경로는 암호화 합성 DB **28,745,728B / 7,018페이지**에서 전체 페이지 인증과 `quick_check`를 검증했습니다. 이번 실제 읽기는 작은 DB 경로였으므로 큰 고객 DB의 실물 성공으로 확대하지 않습니다. 스트리밍 경로의 추가 버퍼·I/O 제한과 전체256MiB Job 제한은 [Windows 사용법](../skills/kakaotalk-mac/references/windows.md)에 구분해 설명합니다.

## Windows에서 확인하고 수정한 경계

- 실제 cp949 출력 경로의 인코딩 문제를 확인하고 reader·probe·manager의 해당 프로세스 표준 출력을 UTF-8로 고정했습니다. 한글·이모지 JSON을 ASCII·cp1252·cp949 출력 조건에서 검사했으며, Windows·카카오톡·보안 설정은 바꾸지 않았습니다.

- 파일 신원 검사에서 `stat`와 `fstat`의 `ctime` 의미 차이로 같은 파일이 변경된 것으로 판정되는 경우를 확인했습니다. Windows 생성 시각은 가능한 경우 `st_birthtime_ns`를 사용하도록 수정했습니다. Python은 Windows의 `st_ctime` 대신 생성 시각에 `st_birthtime`을 사용하도록 안내합니다. [Python 공식 문서](https://docs.python.org/3/library/os.html#os.stat_result.st_birthtime)
- PE 검사에서 raw 데이터가 없는 section의 포인터0을 실제 파일 데이터 범위처럼 해석하지 않도록 구분했습니다. 초기화되지 않은 section은 raw 포인터가0일 수 있고, `SizeOfRawData`와 `VirtualSize`도 같을 필요가 없습니다. [Microsoft PE 형식 문서](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)

자원 제한을 높이거나 파일·프로세스 신원 검사를 생략해 통과시키지 않았습니다.

## x86 후보의 한계

공식 26.9.1.5339 x86 실행 파일은 `Machine=0x14c`, `PE magic=0x10b`와 다음 SHA-256을 확인했습니다.

```text
86f384d1694c74a611181e6c88509e8f59eb8d9739ae3d7789711a9355757500
```

보호된 정적 파일에서 native 함수 경계와 고정 내부 필드는 **NOT_ESTABLISHED**입니다. 구현한 MSVC 구조는 제한된 탐색 후보이며, IKM AES-KW·선택 DB 키 AES-KW·SQLCipher 페이지 HMAC으로 실제 입력을 검증해야 합니다. 합성 검사와 PE32 확인은 실제 x86 읽기 성공을 대신하지 않습니다.

기존 앱이 로그인된 소유자 PC에서 [32비트 검증 절차](windows-x86-probe.md)를 실행한 결과가 필요합니다. x86·x64 실행 파일이 함께 있을 때는 `tools/windows_probe.py run --candidate-x86 --name "정확한 방 이름"`으로32비트 후보를 명시할 수 있습니다. 이 옵션의 합성 검증은 실제 x86 읽기 검증과 별개입니다. 후보는 정식 지원 목록과 stable 자동 적용에서 제외됩니다. 로컬 후보 옵션·해시 목록 수정으로 정식 승인되지 않습니다.

## 배포 판정과 사용 안내

Windows의 한 번의 전체 실행은50초 제한에 도달해 같은 한도 안에서 분할했습니다. 최종399개 고유 검사의 분할 실행은 실패0·건너뛰기20건입니다(핵심17건, 업그레이드2건, 배포 Git 객체1건). 분할 Job의 최대 commit은138,395,648B, 최대 실행 시간은34.323초였습니다. 최종 변경된 source31개·probe39개·manager28개도 통과했으며, 이전28개·33개·26개 결과를 대체해 중복 없이399개로 집계했습니다. 링크 생성 권한이 없는 호스트의 해당 검사와 소스 복사본에 없는 배포 Git 객체 검사는 건너뛴 것으로 남겼습니다. macOS 최종 전체399개 검사는15.394초에 통과했습니다.

v0.4.0 자동 업데이트 manifest에는 이번 소스로 실제 재검증한 **26.9.1.5339 x64만** 포함합니다. 26.8.2.5324 x64의 기존 지원·과거 검증 기록은 유지하지만, 이번 코드로 해당 앱을 재검증했다고 주장하지 않습니다. x86 후보는 포함하지 않습니다.

공개 manager의 실제 다운로드·업데이트·읽기 검사는 정식 asset 발행 이후 수행합니다. 이 커밋 시점 보고서에서 미리 완료로 표시하지 않으며, 결과는 [v0.4.0 릴리스](https://github.com/aixlife/kakaotalk-automation/releases/tag/v0.4.0)의 별도 `public-update-qa.json` asset에서 확인합니다. 실제 x86 성공, 모든 DB 크기 지원, 일반 방 발신, 앞으로의 모든 앱 버전 자동 지원은 이 보고서의 결론에 포함하지 않습니다.

[검증된 업데이트 안내](verified-updates.md)와 [설치·문제 해결 가이드](https://consulting.aixschool.kr/kakaotalk-reader-guide-9c7e3e04b2/)에서 정식 읽기와 후보 시험을 구분해 사용합니다. 공개 보고서에 원본 대화·영수증·계정 파일을 첨부하지 않습니다.

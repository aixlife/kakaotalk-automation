# Windows 호환성과 업데이트

확인 기준: 2026-11-02. 이 도구는 특정 PC·사용자 경로가 아닌 표준 Windows 설치와 본인 계정을 대상으로 한다. 다만 모든 카카오톡 빌드를 지원하는 것은 아니다. **버전, 앱 아키텍처, 실행 파일 해시, 계정·DB 상태를 함께 확인한다.**

## 현재 지원표

| 카카오톡 설치본 | 대화 읽기 | 화면·첨부 실험 |
|---|---|---|
| 26.8.2.5324 x64, 고정 해시 | 기존 실물 검증 범위 | 기존 실험별 검증 범위 |
| 26.9.1.5339 x64, 고정 해시 | 선택 방 실제 3건·원문 대조 | 차단, 새 빌드 미검증 |
| 26.9.1 계열 x86 / 32비트 | 미지원 | 미지원 |
| 그 밖의 버전·해시·아키텍처 | 검증 배포 전 차단 | 차단 |

Windows 64비트, Python 64비트, 카카오톡 64비트는 각각 확인해야 한다. Windows가 64비트라고 카카오톡도 64비트인 것은 아니다. 새 버전 번호만 보고 기존 해시를 교체하면 호환성 확인을 건너뛰게 된다. [실물 검증과 한계](compatibility-QA-20261102.md)를 참고한다.

## 처음 쓰는 사람과 기존 사용자의 순서

1. [설치 안내](installation.md)대로 도구를 설치하거나 기존 정식 설치본을 업그레이드한다. 수정한 포크·개인 규칙을 강제로 덮어쓰지 않는다.
2. 설치한 스킬의 Windows CLI로 `doctor`를 실행한다. 앱 실행·DB 조회·로그인·설정 변경은 하지 않는 검사다.
3. `app_version`, `app_architecture`, `reason`을 확인한다. `READY`라도 실제 읽기는 아직 검증되지 않았다.
4. 준비가 되면 본인이 허용한 정확한 방을 최소 건수로 읽고 원문과 대조한다. 빈 결과를 호환성 실물 성공으로 계산하지 않는다.
5. 날짜 범위 밖이거나 Windows 로컬에 없는 대화는 Mac·모바일·서버의 최신 이력과 다를 수 있다. `earliest_local_message_at_kst`, `latest_local_message_at_kst`를 확인한다.

```powershell
& $python $cli doctor
& $python $cli messages --name "정확한 방 이름" --limit 3
```

`$python`, `$cli`는 [Windows 준비 절차](../skills/kakaotalk-mac/references/windows.md)에서 정한 실제 경로다.

## 차단 원인별 처리

| 결과 | 의미 | 처리 |
|---|---|---|
| `APP_X86_UNSUPPORTED` | 카카오톡 앱이 32비트 | 최신 검증 x64판 사용 여부를 소유자가 결정. x86 유지 지원은 별도 개발·실물 검증 필요 |
| `INSTALLATION_NOT_REVIEWED` | x64여도 해시가 지원 목록 밖 | 검증된 도구 릴리스를 확인. 해시를 수동으로 바꾸지 않음 |
| `WINDOWS_X64_PYTHON_REQUIRED` | Python/OS 조건 불일치 | Windows의 Python 3.11 이상 x64 환경 확인 |
| `APP_NOT_FOUND` / 설치 경로 오류 | 표준 설치 파일을 찾지 못함 | 공식 설치 위치 확인. 임의 경로·다른 빌드로 코드 변경하지 않음 |
| `ACCOUNT_NOT_UNIQUE` | 계정 폴더가 여러 개 남아 있음 | 자동으로 최근 폴더를 고르거나 이전 계정·백업을 삭제하지 않음. 현재는 명시적 계정 선택 기능 미지원 |
| DB/WAL 크기 제한 | 전체 DB 또는 WAL이 24MiB 초과 | 건수 축소로 해결되지 않음. 제한 상향 대신 별도 메모리 절약 구현·검증 필요 |
| 앱/reader RAM·시간 제한 | 정해진 자원 경계 도달 | 중단 결과 유지. 앱 종료·보안 변경·한도 상향으로 강행하지 않음 |

현재 검증한 26.9.1.5339 x64에서는 26.8로 내릴 필요가 없다. 카카오톡 재설치·32→64비트 전환의 로그인·대화 보존 영향은 도구가 관리하지 않는다. 실행 전에 소유자가 확인해야 한다. [카카오 공식 설치 안내](https://pc.kakao.com/talk/notices/ko/2882?agent=win32)와 [다운로드 페이지](https://www.kakaocorp.com/page/service/all)를 이용하며, 구버전 재배포 사이트를 찾도록 안내하지 않는다.

문제를 공유할 때는 앱 버전·아키텍처·Python 버전·차단 코드·도구 릴리스만 전달한다. 대화, 방 이름/ID, 사용자 경로, 원본 영수증, 캡처, 인증 자료는 공개 Issue에 넣지 않는다.

## 앞으로 자동으로 반영하는 구조

현재 구현은 **실행 때 호환성 검사, 정식 설치본의 명시적 업그레이드, 코드 변경 때 Windows·macOS 합성 검사**다. 사용자 PC의 예약 작업·자동 다운로드·자동 재설치·미지 빌드 자동 승인은 등록하지 않는다.

다음 단계는 아래 순서가 적절하다.

1. **변화 감지:** 사용자 PC에서 실행 파일 버전·아키텍처·해시만 비교한다. 바뀌지 않으면 아무 알림도 보내지 않는다. 대화를 읽거나 외부에 업로드하지 않는다.
2. **기능별 호환성 검사:** 새 앱 빌드는 테스트용 Windows에서 본인 계정의 허용 방을 실제 읽고, 원문·페이지 인증·자원 상한·실패·재회수를 검증한다. x86과 x64, 읽기와 화면·발신을 따로 판정한다.
3. **검증본 배포:** 리뷰한 어댑터와 해시 목록을 정식 릴리스로 묶는다. CI 성공만으로 실물 호환성을 승인하지 않는다. 서명자 확인만으로 앱 내부 구조의 호환성이 증명되지는 않는다.
4. **사용자 도구 갱신:** 사전에 자동 업데이트에 동의한 설치에 한해, 수정 없는 정식 설치본을 백업하고 검증한 릴리스로 교체한다. 개인 수정본은 보존하고 알린다. 복구 가능한 교체 실패는 이전 설치로 되돌린다. 강제 종료·전원 중단을 무인 복구하려면 별도 복구 저널이 필요하며 현재 업그레이더에는 포함되어 있지 않다.
5. **예외 알림:** 새 빌드가 아직 검증되지 않았거나 실제 검증이 실패하면 읽기를 멈추고 상태를 알린다. 실패를 숨기거나 매번 동일한 알림을 보내지 않는다.

유지보수 코드 검사는 공개 GitHub 저장소에서 실행하고, 실물 호환성 검사는 별도 Windows 테스트 환경이 맡는다. 새 버전마다 코드 수정이 필요한 경우가 있으므로 **앞으로 어떤 업데이트가 와도 무조건 자동 지원된다는 약속은 하지 않는다.** 고객이 코드를 직접 고치는 부담을 줄이고, 검증된 수정본을 자동으로 전달하는 것이 목표다.

32비트 지원, 여러 계정 폴더의 명시적 선택, 큰 DB를 작은 메모리로 읽는 구현은 아직 남은 공통 지원 과제다. 이 세 가지를 해결하기 전에는 모든 Windows 사용자에게 바로 동작한다고 안내하지 않는다.

# Windows 호환성과 업데이트

확인 기준: 2026-11-02. 특정 PC나 사용자 경로에 맞춘 설치가 아니라, 표준 Windows 설치와 본인 계정을 대상으로 합니다. **버전·앱 아키텍처·실행 파일 해시·계정과 DB 상태**가 모두 맞아야 읽을 수 있습니다. 카카오톡 재설치나 버전 변경으로 검사를 통과시키지 않습니다.

## 현재 지원표

| 카카오톡 설치본 | 대화 읽기 | 화면·첨부 실험 |
|---|---|---|
| 26.8.2.5324 x64, 고정 해시 | 기존 실물 검증 범위 | 기존 실험별 검증 범위 |
| 26.9.1.5339 x64, 고정 해시 | 선택 방 실제 읽기·원문 대조 | 차단, 새 빌드 미검증 |
| 26.9.1.5339 x86, 고정 해시 | **소유자 PC 시험 후보, 실제 읽기 검증 대기** | 미지원 |
| 그 밖의 버전·해시·아키텍처 | 검증 배포 전 차단 | 차단 |

Windows와 Python은 64비트여야 합니다. 카카오톡 앱은 별도로 x64 또는 x86을 확인합니다. 32비트 Windows 운영체제 지원을 뜻하지 않습니다. 기존 x64 검증은 [실물 QA](compatibility-QA-20261102.md), x86 시험은 [검증 도구 안내](windows-x86-probe.md)를 참고하세요.

x86 공식 실행 파일은 PE32와 26.9.1.5339 버전·정확한 SHA-256을 확인했습니다. 보호된 정적 파일에서 내부 함수 경계·고정 오프셋은 확정하지 못했습니다. 후보 코드는 제한된 32비트 구조를 확인하고, IKM·선택 DB 키의 AES-KW와 DB 페이지 HMAC까지 통과해야 결과를 받아들입니다. 합성 시험만으로 실제 x86 지원을 승인하지 않습니다.

## 처음 설치하거나 문제를 확인할 때

1. [설치 안내](installation.md)에 따라 정식 배포본을 설치합니다. 개인 수정본은 보존하고 강제로 덮어쓰지 않습니다.
2. [Windows 준비 절차](../skills/kakaotalk-mac/references/windows.md)에서 정한 `$python`, `$cli`로 `doctor`를 실행합니다.
3. `app_version`, `app_architecture`, `reason`을 확인합니다. `READY`는 준비 상태이고, x86의 `CANDIDATE_READY`도 실제 읽기 성공이 아닙니다.
4. 소유자가 지정한 정확한 방의 최소 건수를 읽고 원문과 대조합니다. 빈 결과·timeout·비정상 종료는 검증 성공이 아닙니다.
5. Windows 로컬 캐시에 없는 대화는 가져오지 않습니다. `earliest_local_message_at_kst`, `latest_local_message_at_kst`와 요청 기간을 함께 확인합니다.

```powershell
& $python $cli doctor
& $python $cli messages --name "정확한 방 이름" --limit 3
```

32비트 시험은 두 번째 명령을 임의 수정하는 대신 [owner-run probe](windows-x86-probe.md)를 사용합니다. 결과의 원문은 본인 PC에만 두고, 공유할 때는 생성된 본문 없는 proof JSON만 전달합니다.

## 여러 계정 폴더와 큰 DB

`accounts`는 대화 내용 없이 계정 폴더의 익명 토큰·DB 크기·수정일·백업명 힌트를 보여줍니다. 복수 계정은 `ACCOUNT_SELECTION_REQUIRED`로 멈추며, 소유자가 확인한 전체 토큰을 `--account-token`으로 지정해야 합니다. 최근 수정 폴더를 자동 선택하거나 백업을 삭제하지 않습니다. 메타데이터만으로 로그인 신원을 확정할 수 없으면 중단합니다.

24MiB를 넘는 DB·WAL과 WAL 반영 후 큰 논리 DB는 작은 버퍼로 페이지를 읽고 인증합니다. 전체 reader의 **256MiB/50초, 실제 읽기40초**는 유지합니다. 스트리밍 경로의 추가 한도는 DB512MiB·WAL256MiB·파일 읽기3GiB·공유 버퍼28MiB·APSW heap32MiB입니다. 이 수치는 성공을 보장하는 크기가 아닙니다. 큰 합성 DB 28,745,728B는 검사했지만 실제 고객 DB와 512MiB DB의 시간 내 성공은 별도입니다.

## 차단 원인별 처리

| 결과 | 의미와 처리 |
|---|---|
| `APP_X86_UNSUPPORTED` | 일반 stable CLI에서 32비트 앱을 발견했습니다. 재설치하지 말고 정확한 후보 해시 여부와 별도 검증 절차를 확인합니다. |
| `CANDIDATE_INSTALLATION_CHANGED` | 시험 후보와 실행 파일이 다릅니다. 버전 표시가 같아도 해시를 바꾸어 통과시키지 않습니다. |
| `INSTALLATION_NOT_REVIEWED` / `NO_VERIFIED_UPDATE` | 현재 앱을 검증한 정식 도구 배포본이 없습니다. 배포 여부를 확인하고 읽기를 중단합니다. |
| `WINDOWS_X64_PYTHON_REQUIRED` | Windows에서 Python 3.11 이상 x64 환경을 확인합니다. |
| `APP_NOT_FOUND` / 설치 경로 오류 | 설치된 공식 파일과 표준 경로를 확인합니다. 임의 빌드·경로로 코드를 바꾸지 않습니다. |
| `ACCOUNT_SELECTION_REQUIRED` | 소유자가 계정을 확인하고 `--account-token`을 지정합니다. 폴더 삭제·최근 계정 추측은 하지 않습니다. |
| DB/WAL·파일 I/O·버퍼 한도 | 스트리밍을 포함한 한도에 도달했습니다. `--limit 1`만으로 해결되지 않을 수 있습니다. 상한을 늘리지 않습니다. |
| 앱/reader RAM·시간 한도 | 중단 결과를 보존합니다. 앱 종료·보안 변경·재시도 반복으로 강행하지 않습니다. |
| `DEPENDENCY_MISSING` | 해당 정식 릴리스의 고정 의존성을 프로젝트 가상환경에 설치합니다. 카카오톡은 바꾸지 않습니다. |
| `LOCAL_PAYLOAD_MODIFIED` / `RECOVERY_CONFLICT` | 관리 파일에 변경·충돌이 있습니다. 수정본과 이전 버전을 보존하고 차이를 검토합니다. |

문제를 공개할 때는 앱 버전·아키텍처·Python 버전·도구 릴리스·차단 코드 또는 생성된 proof JSON만 사용합니다. 대화, 방 이름/ID, 사용자 경로, 원본 영수증, 화면 캡처, 계정·인증 파일은 넣지 않습니다.

## 검증된 수정본 자동 반영

[자동 업데이트 관리 실행기](verified-updates.md)는 프로젝트별 명시 동의 후, 다음 읽기 요청 전에 정식 stable 배포본을 확인합니다. 현재 앱의 정확한 해시·아키텍처에 실물 QA가 연결되고, 고정 GitHub 저장소의 태그·커밋·전체 파일 해시가 맞아야 적용합니다. 수동 Reader의 기존 지원 목록과 자동 업데이트 manifest의 승인 목록은 별도입니다.

- 성공한 확인은 최대1시간 재사용하며, 앱 해시·아키텍처가 바뀌면 새로 확인합니다.
- 현재 호환되는 payload가 온전할 때만 네트워크 실패 후 기존 버전으로 읽습니다.
- x86 시험 후보, 미지 앱 해시, 개인 수정 payload는 자동 활성화하지 않습니다.
- 새 파일을 별도 저장한 뒤 활성 포인터를 교체하고 이전 payload를 보존합니다. 중단 후 다음 `check/read`에서 저널을 확인합니다.
- 예약 작업, 카카오톡 재설치, 로그인·보안·화면 조작, 발신은 포함하지 않습니다.

**자동 반영은 검증된 도구 수정본을 받는 기능입니다. 앞으로 나오는 모든 카카오톡 버전을 자동으로 고치는 기능은 아닙니다.** 새 앱 빌드가 아직 검증되지 않았으면 차단하고, 정식 검증본이 준비된 뒤 적용합니다.

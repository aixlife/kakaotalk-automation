# 내 PC의 AI로 카카오톡 읽기

확인 기준: 2026-11-02

가이드: https://consulting.aixschool.kr/kakaotalk-reader-guide-9c7e3e04b2/
공식 저장소: https://github.com/aixlife/kakaotalk-automation

## 1. 카카오톡은 그대로 두고 시작해요

설치부터 읽기 확인까지 PC의 AI에게 맡기는 안내예요. 카카오톡을 다시 설치하거나 버전을 내리지 않아요.

진행 순서: 환경 확인 → 허용한 방 읽기 → 검증본 업데이트

- **정식 읽기**: 26.9.1.5339 64비트는 실제 읽기를 확인했어요.
- **32비트 시험 후보**: 26.9.1.5339 32비트는 사용자 PC의 실제 읽기 검증이 아직 남아 있어요.

이 가이드는 읽기 전용이에요. 메시지·파일을 보내는 기능은 포함하지 않아요.

[현재 배포본 확인하기](https://github.com/aixlife/kakaotalk-automation/releases)

## 2. 내 컴퓨터에서 일하는 AI를 열어요

Codex나 Claude Code에서 내 PC의 파일을 다루고 명령을 실행할 수 있는 환경을 사용해요. 평소 쓰는 작업 폴더를 열어 주세요.

진행 순서: PC의 AI → 내 PC의 읽기 도구 → 로그인한 카카오톡

- **카카오톡**: 본인 계정으로 로그인된 앱을 그대로 둬요. 읽을 채팅창을 미리 열어둘 필요는 없어요.
- **실행 환경**: Python 3.11 이상 64비트가 필요해요. 카카오톡이 32비트여도 Python은 64비트를 사용해요.

필요한 도구 준비는 AI에게 맡겨요. 계정 비밀번호나 인증 자료를 가이드·공개 게시판에 올리지 않아요.

## 3. 이 문장을 AI에게 보내요

아래 내용을 복사해 PC의 AI에게 붙여 넣으세요. 기존 도구를 고친 적이 있어도 파일부터 지우지 않아요.

진행 순서: 정식 배포본 확인 → 기존 파일 보존 → 설치 준비 검사

```text
https://github.com/aixlife/kakaotalk-automation

이 저장소의 최신 정식 배포본과 설치 안내를 읽고, 현재 작업 프로젝트에서 카카오톡 읽기 도구를 사용할 수 있게 준비해줘.

카카오톡은 다시 설치하거나 버전을 바꾸지 마. 앱 버전과 32/64비트, Python 환경, 기존 스킬 설치 여부를 먼저 확인해줘. Python과 필요한 의존성은 프로젝트용 환경에 준비하고 전역 설정은 임의로 바꾸지 마.

기존에 수정한 파일이 있으면 보존하고 차이를 확인해줘. 정식 설치본은 공식 업그레이드 절차를 사용해. 32비트가 정식 지원 목록에 없으면 해시를 바꾸거나 후보를 자동 업데이트 대상으로 등록하지 말고 시험 후보인지 알려줘.

아직 대화는 읽지 말고 설치 결과와 다음 단계만 쉽게 알려줘. 메시지 발신·계정 폴더 삭제·보안 설정 변경은 하지 마.
```

설치 준비 검사가 통과해도 실제 대화 읽기가 끝난 것은 아니에요.

## 4. 버전과 비트 수를 함께 봐요

AI가 알려주는 카카오톡 앱의 버전과 비트 수를 확인해요. Windows 자체의 비트 수와는 별개예요.

진행 순서: 앱 버전 → 앱 32/64비트 → 정식·후보 구분

- **검증된 64비트판**: 정식 읽기 경로로 진행해요. 내 PC에서도 허용한 방의 실제 읽기를 확인해요.
- **일치하는 32비트 후보**: 다음 화면의 시험 요청을 사용해요. 현재는 사용자 PC 검증 대기 상태예요.
- **지원하지 않는 버전·다른 해시**: 강제로 통과시키지 않고 멈춰요. 검증된 도구 업데이트가 있는지 확인해요.

[지원 범위 확인하기](https://github.com/aixlife/kakaotalk-automation/blob/main/docs/windows-compatibility.md)

## 5. 32비트는 내 PC에서 먼저 시험해요

현재 카카오톡 설치본을 유지한 채 읽기만 검사해요. 아래 요청은 내가 정한 방 하나의 최근 3건 읽기를 허용하는 내용이에요.

진행 순서: 읽을 방 지정 → 후보로 3건 검사 → 본문 없는 결과 생성

```text
현재 카카오톡을 그대로 두고 32비트 읽기 후보를 검사해줘. 기존 정식 도구는 보존하고 저장소에 안내된 공식 후보 배포본을 별도 폴더에 준비해. 후보 안내가 없으면 임의로 만들지 말고 멈춰. 저장소의 후보 안내를 읽고 내 앱의 버전·아키텍처·해시가 허용한 후보와 정확히 일치하는지 먼저 확인해.

검사할 정확한 대화방 이름을 나에게 물어봐. 내가 이름을 알려준 방 하나의 최근 3건만 읽는 것을 허용할게. 답하기 전에는 대화를 읽지 마.

공식 tools/windows_probe.py를 사용하고, 여러 계정 후보가 있으면 공식 accounts 명령으로 확인한 뒤 내가 명시적으로 고른 계정만 사용해. 내가 확실히 고를 수 없으면 멈춰.

검사에 필요한 대화와 읽기 결과는 내 PC에만 두고, 공유할 결과는 대화 내용이 없는 검증 보고서로 만들어줘. 빈 결과를 읽기 성공으로 계산하지 말고, 내 확인 전에는 실제 대화와 일치했다고 쓰지 마.

카카오톡 재설치·해시 교체·계정 폴더 삭제·자원 제한 해제·메시지 발신은 하지 마. 이 후보를 정식 자동 업데이트 목록에 넣지 마.
```

후보 검사 결과가 나와도 정식 지원 승인은 별도예요. 확인되지 않은 상태를 성공으로 표시하지 않아요.

## 6. 실제로 읽힌 3건을 확인해요

64비트 정식판은 아래 문장으로 시작해요. 32비트 시험을 했다면 그 결과 3건이 실제 대화와 맞는지 내 PC에서 확인해 주세요.

진행 순서: 방 하나 선택 → 날짜·내용 확인 → 성공·미확인 구분

```text
카카오톡 읽기 도구로 읽을 정확한 대화방 이름을 나에게 물어봐. 내가 이름을 알려준 방 하나의 최근 3건만 읽는 것을 허용할게. 답하기 전에는 읽지 마.

내 환경에 검증된 공식 읽기 경로를 사용해. 결과가 비어 있으면 성공이라고 하지 말고, 이 PC에 저장된 대화의 마지막 시각과 조회 기간을 구분해 알려줘. 다른 방으로 넓혀 읽지 마.

내가 날짜와 내용을 대조할 수 있게 결과를 이 대화 안에서 보여줘. 메시지는 보내지 말고 원문·방 정보·읽기 영수증을 외부 사이트나 공개 이슈에 올리지 마.
```

이 도구가 읽는 것은 PC에 남아 있는 대화예요. 모바일이나 서버의 최신 이력이 전부 있다는 뜻은 아니에요.

## 7. 대화 내용 없이 결과만 전달해요

32비트 시험을 했다면 검증 보고서만 전달해 주세요. 실제 대화나 화면 캡처를 보내실 필요는 없어요.

진행 순서: 내 PC에서 대조 → 공유용 보고서 확인 → 내용 없이 전달

```text
방금 검사에서 공식 windows_probe.py가 만든 공유용 검증 보고서를 확인해줘.

공유본에는 도구 버전, 앱 버전과 32/64비트, 검사 결과, 건수, 시간·자원 제한 준수 여부, 오류 코드만 포함되는지 확인해. 대화 본문·방 이름·방 ID·계정 식별자·사용자 경로·인증 자료·키·DB·원본 영수증은 넣지 마.

내가 실제 대화와 일치한다고 확인했는지 정확히 구분해줘. 확인하지 않은 항목을 통과로 바꾸지 마. 공유 가능한 보고서 위치와 전달할 짧은 요약만 알려줘. 직접 전송하지 마.
```

보고서를 받은 뒤 검증 결과를 확인해 정식 지원 여부를 판단해요. 보고서 생성만으로 정식 지원이 되는 것은 아니에요.

## 8. 검증된 업데이트만 자동으로 받아요

읽기를 실행하기 전에 정식 도구 업데이트를 확인하는 방식이에요. 카카오톡 앱과 로그인은 그대로 유지해요.

진행 순서: 정식 업데이트 확인 → 기존 버전 보존 → 검증 후 교체

```text
이 프로젝트의 카카오톡 읽기 도구에 공식 관리 실행기를 설정해줘. 검증된 정식 업데이트를 읽기 실행 전에 확인하고, 이전 버전을 남겨두고 검증된 새 버전으로 읽도록 연결하는 데 동의해.

저장소의 tools/reader_manager.py enable 안내를 따라 현재 AI 종류와 실제 프로젝트 경로에 맞춰 설정해. 이후 읽기는 프로젝트의 .kakaotalk-reader/reader_manager.py read 경로를 사용하도록 이 프로젝트에 안내를 남겨줘.

32비트 시험 후보와 미리보기 배포본은 자동 반영하지 마. 개인 수정본은 덮어쓰지 말고 보존해. 카카오톡 재설치·로그인 변경·전역 설정 변경·새 예약 작업 등록은 하지 마.

자동 반영 대상, 실패 시 동작, 중지·복구 방법을 쉽게 알려줘. 다음 카카오톡 버전까지 무조건 지원된다고 약속하지 마.
```

32비트 후보의 자동 반영은 실제 검증 후 정식 지원으로 승인되기 전까지 차단돼요.

## 9. 막히면 삭제보다 진단부터 해요

버전, 계정 후보, 대화 저장 파일 크기마다 원인이 달라요. 검사를 없애서 통과시키는 방식은 사용하지 않아요.

진행 순서: 원인 확인 → 공식 복구 경로 → 같은 범위 재검사

```text
카카오톡 읽기 도구가 막혔어. 기존 앱과 대화 데이터를 보존하면서 공식 진단으로 원인을 확인해줘.

검증된 정식 업데이트가 있으면 공식 관리 실행기로 확인하고 적용해. 설치 경로나 의존성 문제는 프로젝트 환경에서 복구하되 카카오톡은 다시 설치하지 마.

계정 후보가 여러 개면 공식 accounts 결과를 설명하고 내 선택을 받아. 최근 수정된 폴더를 임의로 고르거나 이전 계정·백업을 삭제하지 마. 큰 대화 저장 파일은 공식 메모리 제한 내 처리 경로를 사용하고, 한도를 늘리지 마.

기존 요청의 저장 결과를 회수할 수 있으면 다시 읽기 전에 그것부터 확인해. 해결되지 않으면 버전·32/64비트·오류 코드·시도한 조치만 정리해줘. 원문과 인증 자료는 외부에 보내지 마.
```

큰 대화 저장 파일을 작은 메모리로 처리해도 모든 파일을 보장하지는 않아요. 한도에 걸리면 중단 상태를 그대로 알려요.

## 10. 이제 필요한 방과 할 일만 말해요

검증이 끝난 환경에서만 진행해요. 방 이름과 알고 싶은 일을 좁혀 주면 필요한 대화부터 읽을 수 있어요.

진행 순서: 방·기간 지정 → 읽고 요약 → 근거와 한계 확인

```text
공식 관리 실행기로 검증된 업데이트를 먼저 확인해줘.

읽을 정확한 대화방 이름을 나에게 물어보고, 내가 알려준 방 하나의 최근 24시간 대화 중 20건까지만 읽어서 아직 답할 일과 결정된 내용을 정리해줘. 읽기가 지원되지 않으면 다른 방법으로 우회하지 말고 이유를 알려줘.

원문 근거와 확인하지 못한 내용을 구분하고, 메시지는 보내지 마. 더 오래된 대화나 다른 방이 필요하면 먼저 범위를 알려줘.
```

잠시 멈추려면 읽기 실행을 중단하고 AI에게 공식 관리 도구의 자동 반영 중지 방법을 확인해 달라고 하세요.

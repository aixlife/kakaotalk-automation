검증일: 2026-11-02. Windows의 기존 로그인 세션에서 **KakaoTalk 26.9.1.5339 x64 / Python 3.14.3 / cryptography 47.0.0**을 확인했다. 앱 설치·실행·로그인·보안·화면 설정을 변경하지 않았다. 실행 파일 SHA-256은 `d7781cf275a6f4f23547e8e698005d0e8dbb78e205a34baa2eda3ea158fc64d1`이다.

## 코드·업그레이드 회귀

- macOS: 129개 PASS, 0개 SKIP, Python 소스 35개 구문 검사 PASS.
- 기존 Windows 일반 사용자 세션: 129개 중 122개 PASS, 7개 SKIP, 실패 0. 6개는 심볼릭 링크 생성 권한이 없어서, 1개는 복사본에 이전 Git 태그 객체가 없어서 생략했다. 권한·보안 설정을 바꾸지 않았다.
- Windows 전체 검사 Job: 53,690,368B, 6.429초, 종료코드 0, timeout false. 앱 데이터 읽기 0.
- 신규 호환성 14개: x86·잘못된 PE·미지 해시 차단, 기본 실험 가드 보존, 읽기 CLI만 별도 허용, 실제 해시 영수증, 환경변수·로컬 승인 파일 우회 부재 등을 검사했다.
- 신규 업그레이드 18개: 정식 v0.2.0 LF/CRLF 파일 목록, 백업 무결성, 재실행, 개인 수정·추가 파일·링크·경로 충돌·동시 변경 차단, 복사·활성화 전 실패 복구를 검사했다. 실제 이전 Git 바이트를 쓰는 검사는 macOS에서 통과했다.
- 독립 읽기 전용 검토에서 호환성 14개와 업그레이드 18개를 다시 실행해 통과했다.

GitHub push·pull request에서는 macOS·Windows 표준 runner로 같은 검사를 실행한다. 체크아웃에 이전 태그 객체를 포함한다. 실제 CI 결과는 해당 커밋의 **Source and synthetic checks** 로그로 확인한다. CI에는 카카오톡·계정 데이터가 없으므로 합성 검사 성공을 새 빌드의 실물 성공으로 보지 않는다.

## 남은 제한

**32비트 카카오톡 실물 읽기는 NOT_RUN·미지원이다.** 다중 계정 폴더, 24MiB 초과 DB/WAL, 새 x64 빌드의 화면·발신 실험도 지원 확대로 판정하지 않는다. 현재 변경은 모든 Windows 환경의 해결 완료가 아니다.

업그레이드는 정상 예외 복구와 백업 보존을 검사했다. 강제 종료·전원 중단용 자동 복구 저널은 없으며, 활성화 뒤 외부 변경은 덮어복구하지 않는다. [설치·복구 제한](installation.md#기존-정식-설치본-업그레이드)을 따른다.

대화·방 ID·계정·PC 식별자·캡처·원본 영수증은 공개하지 않는다. 공개 증거는 코드, 합성 테스트, 건수·일치 여부·자원 측정값으로 제한한다. 사용자 PC에 자동 업데이트 예약을 추가하지 않았다.
